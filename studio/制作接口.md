# RPGXP Agent Studio 制作接口

双击便携包的 `Start-RPGXP-Studio.cmd` 打开菜单。需要接入 Agent 时可用 `Start-RPGXP-Studio.cmd mcp`。调用 `studio_projects` 查看原生项目 ID。每个项目都有自己的 `Game.rxproj` 和 `Game.exe`。

## 从游戏需求到 ZIP

1. 把玩法、地图、目标和结局写入 UTF-8 JSON。以工作区里的 `lighthouse.json` 为例。运行 `studio_build`，用新的项目 ID 存放生成结果。要从默认模板逐步搭建时，先调用 `studio_init`。
2. 用 `render_tileset_atlas` 查找瓦片 ID，用 `render_map` 输出地图 PNG。通过 `get_map_events`、`update_map_event` 和 `add_event_command` 查看或改写具体事件。打开 PNG 检查路径、事件位置和构图。
3. 用 `studio_check` 检查起点、地图数据、传送坐标、事件终止指令和数据库的常用素材引用。用 `validate_connectivity` 检查地图间的传送关系。
4. 为关键玩法编写路线并调用 `studio_playtest`。它在临时副本中运行原版 RGSS1，从标题界面进入新游戏。根据失败报告修正项目，直到通过。至少为结局设置一个有区分度的游戏状态断言。
5. 用 `studio_package` 生成 Windows ZIP。包里包含本机 XP 运行时和项目的 Graphics、Audio、Data 等运行文件。解压后运行 `Game.exe`。

可在原版编辑器中打开 `Game.rxproj`。编辑器和 Agent 轮流编辑同一项目。编辑器保存并关闭后，Agent 再写入，避免编辑器将内存里较旧的地图覆盖到磁盘。JSON 批量生成使用新的项目 ID，适合保留可比较的迭代。原生编辑工具直接修改项目文件，改前宜通过版本控制记录当前工程。若 Studio 因进程崩溃遗留 `projects/.locks/<项目>.lock`，确认文件里记录的进程已经退出后，删除对应锁文件即可恢复。

## JSON 规格 v1

- 根对象包含 `version: 1`、`start: {map,x,y}` 和 `maps`。可选 `windowTitle` 为 ASCII 窗口标题，`heroName` 为初始队伍首位角色名，`party` 为初始角色 ID 数组，`font` 为 Windows 字体名，`switches` 为开关 ID 到名称的对象。
- 地图需要 `key`、`name`、`width`、`height`、`floor`。可选字段有 `tileset`（默认 1）、`bgm`（素材名）、`legend`（字符到原生瓦片 ID）、`layers` 和 `events`。地图 ID 按数组次序从 1 开始，宽 20–500、高 15–500。坐标从 0 开始。
- 每个覆盖图层为 `{z,rows}`，`z` 可取 0、1、2，分别对应底层至顶层。每行与地图等宽，`.` 跳过当前格，其他字符从 `legend` 查找。默认 `floor` 填满底层。
- 每个事件为 `{name,x,y,pages}`。页可指定 `sprite`（行走图素材名）、`direction`、`through`、`switch`（开关为 ON 时激活）、`trigger`（`action`、`touch`、`event_touch`、`autorun`、`parallel`）和 `commands`。靠后的可激活页优先。避免给一直激活的自动事件放置会堵住操作的对话。
- 以素材文件名去掉扩展名作为素材引用。当前模板自带默认角色、物品、敌人、敌群和其他数据库。调用 `studio_import_asset` 添加本机素材，再通过原生数据库、地图和脚本工具接入。角色、技能、装备、敌人、职业、状态和脚本的细化由原生工具完成。复杂系统可以在 Main 之前加入 RGSS1 / Ruby 1.8 脚本。

| 事件的 `op` | 其他字段 |
| --- | --- |
| `text` | `text`，换行用 `\n`，每四行分一个消息框 |
| `choice` | `options: [{text,commands}]`，1–4 个选项 |
| `switch` | `id`、`on` |
| `if_switch` | `id`、`then`、可选 `else`，两支均为命令数组 |
| `transfer` | `to: {map,x,y}`、可选 `direction`（2 下、4 左、6 右、8 上） |
| `item` | XP 物品 `id`、可选有符号 `count` |
| `gold` | 有符号 `amount` |
| `battle` | XP 敌群 `troop`、可选胜利命令数组 `win` |
| `sound` | SE 素材 `name` |
| `game_over`、`title` | 进入失败画面或回标题页 |

## 原版运行时试玩

传入 `{project,route}`。省略 `route` 时只加载新游戏并检查出生点。

| 路线步骤 | 行为 |
| --- | --- |
| `{"at":[1,9,11]}` | 等待地图 ID、位置匹配，并且可以操作 |
| `{"move":[8,2]}` | 按方向走两格，适合普通格子移动 |
| `{"interact":true}` | 发送确认键，从角色面向的一侧交互 |
| `{"text":"备用透镜"}` | 等待普通消息包含指定文本，然后确认 |
| `{"choose":1}` | 在对话选项里选第 2 项，从 0 编号 |
| `{"switch":[2,true]}` | 检查开关状态 |
| `{"gold":50}` | 检查队伍金钱 |
| `{"wait":30}` | 等待指定帧数 |

试玩会临时打开 RGSS 游戏窗口。路线适用于原版标题和地图场景。自定义场景、战斗操作和存读档走人工或专用 RGSS 测试。验证器检查已知的数据库素材字段。自定义脚本和事件动态加载的文件需要在运行时测试覆盖。

PowerShell 可通过 JSON 文件调用与 MCP 相同的工具。在源码仓库根目录运行以下命令。

```powershell
$studio = Join-Path $PWD 'studio/studio.mjs'
node $studio call studio_guide
node $studio call studio_playtest ('@' + (Join-Path $PWD 'lighthouse-playtest.json'))
```

## 组件来源

制作器使用本机 Steam 版 RPG Maker XP 的工程模板及运行时。原生文件的读写和地图预览复用 MIT 许可的 [rpgmaker-xp-mcp 1.1.3](https://github.com/SerifeusStudio/rpgmaker-xp-mcp)。便携包自带 Node.js 和锁定的依赖，源码保留同版本的 `package-lock.json`。
